## Proyecto real del TP

Se carga el proyecto base generado del CSV del repositorio, con revisión v7 y adquisición desconocida. Se revisa una muestra de NPHI=**3,3172 v/v** a **8498,8908 m MD** y se acepta su exclusión puntual. La curva original conserva 3,3172; la preparada queda faltante con QC2. La fuente NPHI preparada se activa explícitamente por la aceptación. Los blobs/revisiones originales y parámetros permanecen exactamente iguales.

Undo reproduce el Project previo; redo reproduce la aceptación. Se guarda un snapshot, se retira la receta y se restaura el snapshot: recupera la interpretación aceptada. Guardar/abrir en un navegador nuevo reproduce todas las filas del CSV exportado, incluidas original/preparada/QC.

Se descargan CSV+sumario, LAS+sumario y xlsx. El informe incluye parámetros, fuentes, QC de preparación, diagnóstico zonal de originales, ausencia explícita de DRX y figuras por zona. El HTML de informe no requiere recursos externos y se imprime a PDF con Chromium: 42 páginas en esta selección de contenido/pistas; se verifica texto de preparación y fuente NPHI preparada en el PDF. El proyecto es un recorrido QA con los parámetros iniciales del programa; no se presenta como la resolución final del TP.

## Proyecto sintético y trazabilidad DRX

El generador usa el fixture independiente de P5 para distribuir objetivos de laboratorio y construye un perfil con extremos conocidos. Ejecuta propuesta/aplicación GR y decisión/preview/aplicación de cutoff por sus APIs reales. El informe muestra los 18 puntos, base volumen de sólidos de roca completa, relación constitutiva explícita, referencias sintéticas, GR limpio 25/lutita 135, métricas por bloques y cutoff 0,4→0,5 con impacto registrado. Generarlo no cambia el Project serializado.

Se prueba que cambiar parámetros después de aceptar haga aparecer el registro como histórico con parámetros/revisión modificados. Una coincidencia no se etiqueta como revalidación de hipótesis/soporte. Evidencia de versión futura o corrupta se informa y conserva, escapando el texto del archivo.

## Informe y paquete

La captura de revisión/datum/adquisición y los textos/tablas del nuevo informe no comparten estructuras mutables. La sección de preparación puede omitirse explícitamente; sus opciones no cambian datos ni cálculos. Una prueba modifica únicamente adquisición entre la captura y la finalización: aun compartiendo Well/Interpretation, la generación se rechaza por cambio de revisión.

El [manual autónomo](../manual-entrega.html) está dentro del bundle y se descarga desde la aplicación. El paquete incluye `Interpretacion.html`, `Manual.html`, CSV del TP, TP base, ejemplo sintético, LEEME y manifiesto de integridad. El manifiesto identifica commit y estado sucio de fuente, y enumera tamaño/SHA-256 de cada archivo. Dos empaquetados con los mismos archivos producen bytes idénticos; se verifica cada hash del manifiesto. Nuevas semillas llevan ids/fechas normales y pueden cambiar esos bytes.

HTML de producción verificado: **5796684 bytes**, SHA-256 `4743632e985f5ca7fd79a6c24c6ebad1f67102ef0265817c4e7611d190736349`. El ZIP final se genera después del commit para que su manifiesto registre una fuente limpia. Su SHA se registra junto al artefacto generado y en el masterplan; no se agrega el build al repositorio.

## Evidencia y reproducción

[Resultado del navegador](2026-11-01-entrega-p8/result.json), [captura imprimible](2026-11-01-entrega-p8/informe-diagnostico.png), [índice de artefactos generados](2026-11-01-entrega-p8/artifacts.json). Los archivos completos se generan localmente con el script, evitando duplicar decenas de MB de curvas/figuras en Git. Se conservan fuentes, comandos y hashes de la ejecución. Los informes y proyectos del recorrido son QA y están separados de cualquier entrega académica final.

```sh
npm ci
npm run typecheck
npm test -- --maxWorkers=1
npm run build
node scripts/qa/delivery-seed.mjs /tmp/p8-seed
python -m http.server 4178 --directory dist
# Otra terminal, con Playwright Python y Chromium:
python scripts/qa/delivery.py --seed /tmp/p8-seed --output /tmp/p8-browser
python scripts/build-delivery.py --projects /tmp/p8-seed --output dist/entrega-p8.zip
```

Para verificar el ZIP, se compara cada ruta/tamaño/SHA de `manifest.json` con su contenido descomprimido. Para la apertura por doble clic, extraer el ZIP y abrir `Interpretacion.html` en un navegador que permita archivos locales; comprobar que llega a «Listo» y que puede abrir el proyecto TP. El estado automatizado file:// se conserva como bloqueado, separado del offline HTTP que sí pasó.

La regresión completa cubre módulos, lectores, proyectos antiguos, protocolo, preparación, DRX/calibración/cutoffs, MGT y diagnóstico P7. No se repite una campaña completa de temas/DPR/tacto ni benchmarks ajenos a los cambios del informe. El vídeo y ampliaciones fuera de este alcance siguen en sus pendientes; no se cierran #31/#32 ni se integra main.
